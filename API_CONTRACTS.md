## Naming contract
`destId` everywhere — always the canonical slug from Ananya's seed
(e.g. `"manali"`). Never a Google Place ID, never a display name.

## Password policy (`backend/src/lib/passwordPolicy.js`, mirrored in `frontend/src/lib/passwordPolicy.js` for live UI feedback — backend is authoritative)
8–128 chars, at least one uppercase, one lowercase, one number, one special character (e.g. `Sahyatri@2026`). Enforced identically on signup, reset-password, and change-password. Never trust the frontend's check alone — every one of those three backend routes re-validates independently.

## Auth tokens (`backend/src/models/authToken.model.js`)
Single-use, time-limited, purpose-scoped (`email_verify` 24h / `password_reset` 1h). Only `sha256(rawToken)` is ever persisted — the raw token exists only in memory and in the emailed link, never in a log line. Issuing a new token for the same `(userId, purpose)` invalidates any prior one. A TTL index cleans up expired rows (with a 1h grace period past `expiresAt` so an honest "expired" response stays possible right up to cleanup).

## Auth rate limits (`backend/src/middleware/authRateLimit.js`)
Per-IP: signup 10/hr, login 15/15min, forgot-password 5/hr, reset-password 10/hr, verify-email 10/hr, resend-verification 5/hr. Tuned to block brute force without locking out a legitimate user's typo-retries.

## Frontend auth routes
Public: `/`, `/signin`, `/signup`, `/forgot-password`, `/verify-email`, `/reset-password` — the last three are never gated on auth state (a logged-in user following a stale email link still needs them to work). Authenticated: `/home`, `/profile`. Role-specific: `/operator`, `/authority`. There is exactly **one** sign-in page for all roles — no separate traveller/operator/authority login screens; the frontend never lets a user pick their own role, on signup or anywhere else. Post-login redirect reads the role from the `login` response / `GET /api/auth/check`, never from client state: `traveller → /home`, `operator → /operator`, `authority → /authority`.
